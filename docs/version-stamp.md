# Version stamp (item 389)

The About box and diagnostics show `VERSION`, generated by
`lapce-core/build.rs` into `meta.rs`:

- Release builds (`RELEASE_TAG_NAME` starting with `v`, or the
  `distribution` feature): the plain `Cargo.toml` version, e.g.
  `0.4.6`.
- Anything else: `<version>+<Debug|Nightly>.<short-hash>`, with a
  `-dirty` suffix when tracked files had uncommitted changes at the
  moment the build script last ran - e.g. `0.4.6+Debug.fa8ee06-dirty`.

## Cache provenance

Cargo caches the build script output and re-runs it only when a
declared input changes (mtime comparison). The script declares:

- `build.rs`;
- `<gitdir>/HEAD` - moves between branches or on detach. `.git` is
  resolved through the `gitdir:` pointer file when the checkout is a
  linked worktree;
- `<commondir>/refs/heads` - declared as a DIRECTORY, which cargo
  scans recursively. A new commit rewrites the branch's loose ref
  file, and the packed-to-loose transition creates that file; the
  directory scan catches both. Tracking HEAD alone left the baked-in
  hash stale, because committing does not rewrite `.git/HEAD`;
- `<commondir>/packed-refs`, when it exists - covers commits while the
  branch ref is packed.

Branch refs live in the common dir shared by all worktrees, so the
`commondir` file is resolved as well. Only existing paths are
declared: cargo cannot stat a missing path and re-runs the script
every time, which would rebuild `lapce-core` (and everything
downstream) on every invocation.

The hash is resolved with `git show` pinned to `CARGO_MANIFEST_DIR`
(git2 on non-Linux), so it always names THIS repo's HEAD regardless of
the caller's working directory.

## Limits

- The stamp - including `-dirty` - reflects the tree as of the last
  build-script run, not the current instant: edits made after that run
  change no declared input and re-trigger nothing, so a clean-looking
  stamp can lag a freshly dirtied tree until the next commit, env
  change or clean build. Treat the hash as "built from at least this
  commit", never as proof of a clean tree; verify with `strings` or
  `cargo clean -p lapce-core` when it matters.
- A shared `CARGO_TARGET_DIR` across different checkouts relies on
  each checkout's git files being written on checkout/commit, which
  git does with fresh mtimes.
